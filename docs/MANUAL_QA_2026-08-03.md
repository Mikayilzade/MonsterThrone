## Remaining Stage 2A closure items

### A. Sanctuary predator return loop

A high-aggro predator such as the red Shadow Wolf retreats after unfair sanctuary damage, but immediately turns back and returns to the protected hero. This recreates a safe repeated-hit exploit.

Expected behavior:

- after receiving unfair damage from a protected hero, the creature retreats beyond a distance appropriate to its own aggro radius, not one fixed distance for all species;
- add a temporary sanctuary-avoidance/disengage state so it cannot immediately reacquire the protected hero;
- while avoidance is active, it should move away or resume normal wandering outside the area;
- attacking it again from sanctuary refreshes/strengthens the retreat instead of creating an approach-retreat loop;
- after the hero leaves sanctuary, or after a sensible cooldown and distance, normal AI may resume;
- add regression coverage for the Shadow Wolf, whose aggro radius is larger than the current generic disengage distance.

### B. Desktop camera zoom

Mobile pinch zoom works, but desktop has no zoom control.

Expected behavior:

- mouse wheel zoom on the game canvas;
- optional keyboard alternatives such as `-`, `+` and reset-to-100%;
- use the same clamp and locally persisted display preference as mobile pinch zoom;
- wheel zoom must not scroll the page while the pointer is over the game canvas;
- preserve camera-centered rendering, culling and combat-overlay alignment.

### C. Target-lock cancellation on empty taps

Current mobile behavior cancels the selected target when the player taps empty world space. During combat this can happen accidentally and makes the lock appear unreliable.

Preferred behavior:

- tapping another creature switches target;
- tapping the currently selected creature again may cancel it, or provide a small explicit cancel-target control;
- ordinary empty-world taps should not cancel a valid locked target;
- target still clears on death, unload and break distance;
- add a regression test for empty tap preserving target lock.

### D. Remaining mobile HUD collision

The biome badge can still overlap the interaction prompt/hotbar area in portrait mode (`Каменистые возвышенности`, `Луга`).

Expected behavior:

- biome badge must occupy its own reserved HUD position;
- interaction prompt and toasts must remain fully readable;
- biome badge must never cover hotbar slots or the minimap;
- verify at the same iPhone portrait viewport with Safari bottom controls visible.

## New Stage 2B combat-state idea

Creatures may react to serious wounds instead of always preserving identical movement:

- a wounded/limping state can reduce speed by a visible percentage;
- a rare panic or rage reaction can temporarily increase speed/aggression;
- reactions should be tied to health thresholds, damage type, critical hits, species temperament and/or body-part injury rather than arbitrary invisible randomness;
- show a clear icon/text and percentage so the player understands why speed changed;
- save the temporary state correctly across sector unload/load;
- avoid making every successful hit a guaranteed slow.

## Clarification from current implementation

The current generic `slow` status is produced by traps. Ordinary spear wounds do not currently slow creatures. The Leafhorn is simply a relatively slow grazer and can therefore feel as if it slows further while the hero catches it.
